# 编译与实际运行验证

验证环境为 Ubuntu 26.04.1 x86_64、GCC 15.2.0、CMake 4.2.3、Ninja 1.13.2、ns-3.49、uv 0.12.1 和 Python 3.12.13。

Python 解释器由 uv 标准用户目录提供，项目依赖安装在 `.venv`，版本由 `uv.lock` 固定。CMake FetchContent 获取 nlohmann/json 3.12.0 并校验 SHA-256，构建产物保存在 `build`。

在独立的 `build/reproduce` 目录重新配置、获取依赖和编译后，真实传输场景完整交付 21,150,176 字节。应用提交、接收和 ACK 确认字节数一致，截止时待交付字节数为 0。该运行保存在 `results/validation/reproduced-transfer`。

**实际网络验证覆盖传输、恢复与资源竞争。** 自动测试检查应用提交、网络发送、重传、接收及 ACK 字节计数，确定性丢包后的重复 ACK 与快恢复，链路中断后的超时恢复，以及五种窗口保留比例对应的阈值公式。测试还覆盖 CUBIC 与 Reno 竞争、传播时延变化、连接加入、反向流量、重复运行和指标汇总。

实际 GLM 测试验证 API 返回模型、JSON 结构、决策编号、动作生效、100 ms 至 1 s 决策延迟，以及保存动作的精确重放。跨进程接口测试启动两个真实调用进程，核查请求串行执行和排队时间。

完整测试共 22 项，全部通过。测试报告保存在 `results/validation/pytest.xml` 和 `results/validation/pytest.log`。CTest 的 `network-integration` 已通过，使用真实 ns-3 运行验证非 API 测试；Ruff 检查及 uv 锁定、环境一致性检查均通过。

**容量变化运行采用方案规定的时间。** 第 60 s 将瓶颈从 20 Mbit/s 调整为 5 Mbit/s，第 120 s 恢复为 20 Mbit/s，第 180 s 停止提供新数据，仿真运行至第 210 s。以下为各算法一次独立运行的有效吞吐量。

| 算法 | 第 20 至 60 s | 第 80 至 120 s | 第 140 至 180 s |
| --- | --- | --- | --- |
| Reno | 19.280120 Mbit/s | 4.820102 Mbit/s | 19.280120 Mbit/s |
| CUBIC | 19.280989 Mbit/s | 4.841822 Mbit/s | 19.280989 Mbit/s |
| GLM 控制的 Reno | 19.280989 Mbit/s | 4.820102 Mbit/s | 19.280989 Mbit/s |

这三次运行均为单连接场景。多连接公平性通过竞争测试和实验矩阵评价。统计程序支持独立重复的 95% 置信区间和相同运行编号的配对比较；表内每个算法的样本数量为 1。

对应运行目录为 `results/validation/capacity-reno-01`、`results/validation/capacity-cubic-01` 和 `results/validation/capacity-glm-01`。三个无损容量参考运行保存在同一目录下的 `reference-5-01`、`reference-20-01`、`reference-50-01`。

GLM 容量变化运行保存了 185 次真实模型决策和 43 次阈值计算事件。模型选择的比例分布为：0.5 共 61 次、0.6 共 91 次、0.7 共 31 次、0.8 共 2 次。按预定恢复判据，容量下降后的恢复时间为 3.3 s，容量恢复后的恢复时间为 1.0 s。模型调用耗时中位数约 3.56 s，P95 约 5.18 s；该运行采用零仿真决策延迟。

**诊断结果按实际丢弃事件核验。** 在这次容量变化运行中，模型对全部 185 个窗口输出 `no_loss`。其中 139 个窗口的实际标签为无丢包，46 个窗口存在队列丢包。因此该运行的分类准确率为 75.14%，对存在队列丢包窗口的识别数量为 0。原始观测、解释与动作分别保存在 `decisions.jsonl` 和 `api` 目录，分类表现与网络控制指标分别记录。

每次分析生成 `metrics.json`、`curves.png` 和 `curves.pdf`。汇总结果位于 `results/validation/summary.json`，同时提供 `runs.csv` 和比较图。

**固定观测一致性实验完成 150 次真实请求。** 从 Reno 容量变化运行中抽取 30 个实际观测，每个观测独立请求 5 次。在这 30 个样本中，各自重复请求的窗口保留比例和诊断分类均一致。输入、逐次请求响应及统计结果保存在 `results/validation/consistency`。

**完整矩阵包含 96 个场景，每个场景 20 次独立重复，共 1920 项运行配置。** 清单位于 `results/formal-matrix/manifest.json`。当前记录覆盖实际功能测试、完整时长的容量变化运行和无损参考运行；1920 项正式实验尚未全部执行。

Linux 已完成实际编译和运行。macOS 使用相同的 uv、CMake 和测试入口，当前执行环境未提供 macOS，macOS 的实际编译与运行尚未验证。
